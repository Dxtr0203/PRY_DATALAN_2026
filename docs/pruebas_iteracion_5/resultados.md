## Resumen de ejecución e impedimentos

- Se creó y verificó una base PostgreSQL temporal distinta de la base operativa. La preparación protegida creó cuentas ficticias y configuró tres perfiles técnicos.
- Se comprobó el acceso con cliente HTTP de Django, no mediante navegador: las ocho cuentas iniciaron sesión con el rol esperado y una ruta de Sistemas rechazó la sesión Comercial.
- La suite completa ejecutó 128 pruebas: **125 aprobadas, 1 fallida y 2 con error**. La falla fue la expectativa de `REPORTADO POR:` en `test_systems_incidents_page_shows_interactive_support_reports`. Los errores de fechas fijas pasadas se produjeron en `test_eventual_inspection_deadline_uses_commercial_end_date` y `test_plant_technician_sends_tentative_inspection_details_to_assigned_support`; ambos terminaron además en error de middleware de mensajes al usar `RequestFactory`.
- Las 10 pruebas focalizadas seleccionadas terminaron correctamente. La mayoría de las pruebas de vistas usan mocks; no se contabilizan como persistencia real.
- La comprobación de P5-15 sí utilizó PostgreSQL real: las filas guardaron valores distintos, pero las funciones lectoras retornaron valores por defecto. El registro conserva tanto las filas como los valores leídos. No se modificó el código para ocultar el fallo.
- El navegador integrado pudo abrir el login del servidor aislado, pero no se completaron los recorridos de solicitud permanente, eventual o incidencia. No se fabricaron capturas.
- P5-04 difiere del flujo pedido: no se encontró una acción para resolver una observación comercial posterior a la derivación y reenviar la solicitud.
- P5-11 difiere del modelo solicitado: las etapas existentes guardan texto libre, no distinguen explícitamente modalidad remota/campo y el cierre exige revisión de conclusión por Soporte.
- La fecha efectiva de ejecución fue 27/10/2026. El retiro eventual no se simuló ni se adelantó el reloj.
